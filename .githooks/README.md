# git 훅

## 켜는 법 (클론마다 한 번)

```bash
git config core.hooksPath .githooks
```

훅은 저장소에 있지만 `core.hooksPath`는 클론마다 따로 켜야 한다. git이 남의 저장소를
받자마자 훅을 실행하면 그 자체가 보안 문제이기 때문에 그렇게 되어 있다.

## pre-push — 비공개 이름 검사

`scripts/check-private-names.sh`를 부른다. 훅 자체는 그것만 한다 — 훅이 커지면 아무도
읽지 않고, 읽지 않는 훅은 `--no-verify`로 꺼진다.

**왜 있나.** 이 저장소는 공개다. 2026-09-07에 근무표 기능을 만들면서 동료 실명이 두 곳에
들어갔다. 테스트 픽스처의 이름으로 한 번, 그리고 측정 기록에 "이름이 흔들렸다"를 적으면서
그 이름 자체로 한 번. 둘 다 푸시 전에 잡았지만, 잡은 것은 사람이 한 번 더 훑었기 때문이지
무엇이 막아준 게 아니었다.

**이름 목록은 저장소 밖에 둔다.** 안에 두면 막으려던 것을 커밋하는 셈이다.

- 기본 위치: `<저장소 부모>/.private-names`
- 바꾸려면: `PRIVATE_NAMES_FILE=/경로 git push`
- 형식: 한 줄에 이름 하나. `#`으로 시작하는 줄과 빈 줄은 무시한다.

**무엇을 보나.** 이번에 올라가는 커밋들의 **추가된 줄**만 본다. 삭제한 줄까지 걸면 이름을
지우는 커밋 자체가 막힌다.

**걸리면.** 이름은 출력하지 않는다 — 터미널 기록과 CI 로그에 남는다. 몇 곳에서 걸렸는지와
찾는 방법만 알려준다.

**목록이 없으면** 통과시키되 매번 알린다. 없다고 막으면 새로 받은 곳에서 아예 푸시가 안 되고,
그러면 `--no-verify`가 습관이 된다. 습관이 된 훅은 없는 것과 같다. 다만 목록이 **있는데**
이름을 하나도 읽지 못하면 막는다 — 그때는 통과가 아니라 고장이다.

### 직접 돌려보기

```bash
bash scripts/check-private-names.sh origin/dev-playground..HEAD
```

### 알고 있는 함정

- **CRLF.** 메모장으로 목록을 편집하면 줄 끝이 `\r\n`이 되고, 그러면 `이름\r`을 찾게 되어
  아무것도 안 걸린다. 스크립트가 `\r`을 떼지만, 이 검사는 실제로 그렇게 한 번 조용히
  통과했다. 조용한 통과가 이 훅의 가장 나쁜 실패 방식이다.
- **히스토리는 안 본다.** 이번 푸시의 변경분만 본다. 이미 원격에 올라간 것은 이 훅의 범위가
  아니다.
