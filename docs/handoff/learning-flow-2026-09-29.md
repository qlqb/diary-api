## 1. 확인한 원인 (이전 조사 단서와 대조)

| 단서 | 확인 결과 |
|---|---|
| 완료 기준이 있으면 행동 설명이 숨는다 | 맞다. 게다가 생성기가 description을 "행동 · 완료: 기준"으로 합쳐 저장해, 숨겨진 것이 **유일한 행동 문장**이었다. AI 경로의 sourceLocator는 늘 null이라 시작 위치도 없었다 |
| 단계 안내가 초안에서만 쓰인다 | 맞다(`mode="item"` 사용처 없음). 추가로 부분 수행으로 남은 조각은 제안 원본을 찾지 못해 404, 메모는 안내 행이 있어야만 남길 수 있었다 |
| 자기평가·실행 피드백은 이미 있다 | 맞다(blocker_kind·메모·자기평가). "혼자/도움"·"막힌 단계"는 없었다 |
| 예전 분석만 교재를 저장, 자동 분석엔 경로 없음 / 버튼이 숨는다 | 맞다. 업로드마다 CONTENT 작업이 생겨 버튼은 사실상 닿을 수 없었고, 옛 적용은 토픽을 덧붙이고(중복 방지 없음) 교재는 빈 칸만 채웠다 |
| 목차·본문을 올렸는데 토픽이 안 생김 | **다른 원인**: 정리는 사용자가 누를 때만 돌고, 구간 추출에서 목차 계층이 사라지며, 큰 목차는 출력 한도에 걸릴 수 있다. 버튼 문제가 아니다 |
| 트리 편집 기능이 있다 | 서버 적용기(TopicTreeEditor)만 있고 **UI 편집기는 없었다**. 트리를 바꾸는 길은 정리안 적용뿐. 병합은 자료 연결만 옮기고 `merged_into`는 아무도 읽지 않았다 |
| MOVE는 맨 뒤, 정리 요청에 지시 없음 | 맞다 |
| 주차별 보기는 미확정 정보 | 09-22 작업이 확인된 자료 주차로 바꿨다(미커밋이었음) |

이번에 따로 찾은 결함: `ExecutionItemService.complete()`의 `@Transactional`이 정적 메서드 위에 붙어 트랜잭션 밖이었다.
학습 지도의 계획·완료 수가 `BETWEEN NULL AND NULL`로 날짜 있는 실행 항목을 전부 빼고 셌다. 학습 지도 상세가 출처 필드를 받지
못해 모든 항목을 "원문 근거 없이 AI가 세분화"라고 말했다. 셋 다 고쳤다.

## 5. 남은 한계

- 새 마이그레이션은 **로컬 `memo`에 적용하지 않았다**(확인: memo에 새 표 0, 새 열 0). 이 브랜치로 사용자 서버를 띄우기 전에 적용해야
  한다 — 없으면 실행 기록 조회·완료가 `Unknown column support_level`로 실패한다.
- 교재 규칙 추출은 흔한 판권면·목차 모양만 읽는다. 스캔 PDF·표 목차·쪽수가 다른 줄에 있는 목차는 "미확보"가 된다. 제목은 이름표가
  있을 때만. 외부 도서 검색은 도입하지 않았다.
- 트리가 이미 있을 때 목차로 빠진 장만 제안하는 경로는 모델 판단이며 실제 모델로 돌려 보지 않았다(빈 트리 골격만 확인).
- 시험 범위 제외는 이름(label)으로만 구분하고 시험 일정과 잇지 않는다.
- 직접 조작의 [나누기]는 근거 구간을 고르지 않는다(말로 요청하면 근거 구간으로 나눈다).
- 초안 화면에서 시작 도움을 받는 UI는 두지 않았다(API는 있다). 초안에서는 「자세히」, 적용 뒤에는 작업 공간.
- 상담 패널에서 바로 구조를 바꾸지는 않는다 — 말로 한 구조 요청은 프로젝트의 정리 구역에서 한다(작업 공간은 조정 상담을 연다).
- 검증 DB `memo_flow_verify`·`memo_test`에 합성 행이 남아 있다(사용자 DB 아님).
