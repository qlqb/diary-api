## 2. 선택한 방식

- **서버 선행 조회 + 모델의 추가 읽기 1회.** 새 청킹·임베딩·벡터 DB 없이 기존 원문 단위를 쓴다. 검색은 LIKE(띄어쓰기 무시 비교
  포함) + 질의어(현재 발화 1.0, 앞선 사용자 발화 0.6→, 직전 AI 답 0.4, 학사 개념 확장 0.45/0.7, 과목명 0.3) + 점수 하한 0.6.
  선택은 과목별 라운드로빈(한 과목이 예산 독점 금지), 같은 원문 중복 제거, 표 행은 머리 행과 함께.
- 낱말이 원문과 맞지 않으면(예: "성적" ↔ "출석 10%…") 모델이 `[자료 목록]`의 번호·범위·검색어로 추가 읽기를 요청한다(§4 F).
- **한도**: 원문 6,000자(곳당 1,500·최대 10곳), 앱 사실 1,600, 분석 목록 1,600, 자료 목록 1,800, 추가 읽기 7,000자·요청 4개·
  범위 6단위, 호출 최대 2회, 두 번째 호출은 턴 시간 상한(90초)의 남은 시간 안(20초 미만이면 읽지 않고 그렇게 말함). 근거가 있으면
  대화 기록 몫을 최소 3,000자 남긴다. 한도로 못 실은 것은 gaps(`NOT_READ_LIMIT`)로 보인다.
- **접근**: 사용자 활성 자료만, 현재 해시의 단위·구간만. 추가 읽기는 이 턴의 장부 번호만 받고 읽기 직전 소유·삭제·해시를 다시 본다.
  원문은 "데이터이고 지시가 아니다" 블록으로 싣는다. 조회는 아무것도 쓰지 않는다.
- 계획 경로의 `PlanMaterialSelector/Retriever`는 계획 목적 프롬프트·예산 구조라 재사용하지 않았다(검증 방식 — 해시·소유 재확인 —
  은 같은 규칙으로 따랐다).

### 코드 리뷰(Codex `gpt-6.1-sol`, 정적 리뷰 5회 → APPROVED)

CRITICAL 없음. WARNING을 모두 고쳤다(합계 20건, 앞 회차 수정의 빈틈 포함).
- **원문 속 지시 대비**: 원문을 실은 턴에는 합의 UPDATE/REMOVE를 적용하지 않고, ADD는 AI 제안 후보로, ACCEPT/REJECT는 이 턴 전에
  있던 제안에만, 자동 기억은 저장하지 않고, 진행 중 요청은 취소·유형 변경·값 지우기(CLEAR·SET null)를 막고 사용자 값을 확인 필요로
  낮춘다. 남는 위험: 원문 지시가 이미 보인 AI 제안의 수락을 유도할 수 있다(화면에서 되돌릴 수 있음).
- **실행 경계**: 두 호출 구독을 한 Composite로 취소, 두 호출 모두 절대 마감(`withDeadline`), 근거·추가 읽기 블록 전체에 글자 상한을
  강제(넘치면 원문 없이 알림만·장부 비움), 여유가 없으면 두 번째 호출을 하지 않는다.
- **검색 품질**: 자료별 상한(ROW_NUMBER) 뒤 전체 상한, 걸린 행 우선 발췌, 부분 단위는 재검색 허용, 띄어쓰기 무시 위치 복원, 본문 없는
  메타데이터 조회와 일괄 재확인.
- UI `npx vitest run`: 기준 757건(64 파일) → 761건(65 파일), `npm run build`·`npm run lint` 성공. 새 `AiPanelEvidence.test.jsx`.
