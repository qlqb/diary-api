# 교재 목차 하위항목 보존 — 작업·검증 기록 (2026-10-06)

브랜치 `feat/toc-subitems`(diary-api `wt/api-toc`, diary-ui `wt/ui-toc`), 기준 dev-playground(api `8268554`, ui `a314d84`).
계획 `docs/handoff/toc-subitems-plan-2026-10-06.md`(v2 + 재리뷰 반영 + 구현 중 바뀐 것), 마이그레이션 `docs/sql/2026-10-06-toc-subitems.sql`.

## 1. 범위

사용자 질문 "목차를 찾긴 하는데 왜 하위항목은 버려지는 것 같지?"에서 시작. 외부 검토 의견(완료 조건 5개 + 줄 번호 보완 3개)을 계획에 넣었다.
1단계: 웹 목차 읽기 복구, 원문 열쇠, 옛 리비전 재구조화, 확실히 대응된 기존 토픽 아래 빠진 항목 ADD, 문제 지어내기 차단, 목차 접기 화면.
다음 단계(보류): 자료 기반 트리와 목차의 의미 대응(`sameAs`), 원문이 바뀐 뒤 열쇠 재연결, 업로드 목차 규칙 확장.

코드 리뷰 1회차 반영: COVERED는 목차 출처 없는 토픽만·한 토픽 한 항목, 서버 ADD와 같은 모델 ADD 제거(연결은 서버 tempId로 옮김), 재구조화 리비전의
최신 승격을 원자적 조건 UPDATE로, 모델 보완이 상한에서 규칙 항목을 밀어내지 못함, 쪽수는 구분자가 있을 때만(제목 끝 숫자 보존), 일회 변환은
정확 비교, 계획 구간 근거에 연결 토픽 전부(`linkedTopicIds`).

### 2.1 코드 재리뷰

서버 목차 추가안과 겹치는 모델 ADD 제거를 고쳤다: 목차 확인(TocOps)보다 먼저 정리해 열쇠가 같은 모델 ADD를 가리키던 LINK도 서버 tempId로
옮기고, 뺀 항목이 든 구간은 서버 항목 LINK로, 그 자식은 서버 항목 아래 ADD로 옮긴다(옮긴 자식도 다시 본다). 별칭을 끝까지 모은 뒤 판정해
모델이 자식을 부모보다 먼저 내도 같다. 회귀 테스트 추가.
