# 오늘조각 제품 가설

## 한 문장

계획을 만들어주는 앱이 아니라, 사용자의 실제 실행을 관찰해 학기 계획을 계속 다시 계산해주는 시스템.

사용자 언어로: **"내 일정과 공부 속도를 기억해서, 지금 뭘 해야 할지 대신 판단해주는 앱."**

AI가 대신하는 것은 생활이 아니라 계산이다. 남은 시간, 진도 대비 지연, 속도 배율처럼 사람이 매번 머리로 다시 계산하기 어려운 값을 앱이 계속 갱신한다. 판단 재료는 앱이 만들고 결정은 사용자가 한다.

A+를 보장하지 않는다. 대신 다음 네 판단을 매번 머리로 다시 계산하지 않게 한다.

- 오늘 뭐 하지?
- 어느 과목부터 하지?
- 밀렸는데 어떻게 하지?
- 이 속도로 괜찮나?

## 4층 구조

### 1. 현실층

앱이 확실히 아는 사실을 관리한다.

- 과목
- 시험
- 수업
- 알바
- 루틴
- 가용시간
- 진도

AI 추측 금지. 여기가 틀리면 위의 모든 최적화가 정교하게 틀린 답이 된다.

### 2. 판단층

현재 상태를 바탕으로 다음을 계산하고 해석한다.

- 무엇이 급한가
- 얼마나 필요한가
- 어떤 순서가 좋은가

규칙 계산(Timefold)과 AI를 같이 쓴다. 산수를 언어모델에 맡기지 않는다.

### 3. 실행층

사용자는 계획 문서가 아니라 다음을 본다.

- 지금 할 것
- 다음 할 것
- 오늘 남은 것

### 4. 관찰층

완료, 실제 소요시간, 이동, 축소, 보류를 수집해 현실층으로 되돌린다.

```text
현실 파악
→ 우선순위
→ 배분
→ 실행
→ 관찰
→ 상태 갱신
→ 재판단
```

이 루프가 제품이다. 계획 생성기는 이 루프 안의 함수 하나다.

## 원칙

- 관찰 데이터에 추정값을 채우지 않는다. 모르면 `NULL`로 남긴다.
- 학습트리(`course_topics`)는 판단의 재료이지 중심 구조가 아니다. 삭제가 아니라 강등한다. 선행관계가 실제로 필요해지면 그때 추가한다.
- 실패 프레이밍 금지. 안 한 날은 기록이 없는 날이지 실패한 날이 아니다.

## 일주일 실사용 관찰 질문

| 질문 | 볼 것 |
|---|---|
| 배분이 현실적인가 | 계획시간 대비 실제시간 |
| AI 판단이 도움이 되는가 | 추천을 그대로 수행/수정/거절 |
| 계획이 행동으로 이어지는가 | 계획 항목 중 실제 시작 비율 |
| 무엇 때문에 어긋나는가 | 시간부족/난이도/피로/외부일정 |
| 재계획이 필요한가 | 이동·축소·보류가 발생한 순간 |
| 판단 부담이 줄었나 | "오늘 뭐하지"를 따로 고민한 순간 |

핵심 수집 값은 `estimatedMinutes`와 `actualMinutes`다. 이 둘만 1~2주 모여도 "웹서버를 평균 1.5배 과소평가한다" 같은 개인 모델이 시작된다.

## 확장 순서

학기 운영(지금) → 루틴·수면·알바 반영 → 프로젝트·취업 준비 → 생활 전반.

처음부터 개인 운영 AI를 만드는 게 아니라, 학기라는 폐쇄된 세계에서 먼저 성공시킨다.
