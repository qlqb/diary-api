# 08. Today / Execution Loop

## 1. 목적

이 문서는 오늘 탭과 실행 탭이 같은 데이터를 보면서도 서로 다른 책임을 갖도록 경계를 고정한다.

과거 문서의 `Today = ScheduleBlock 중심`, `Todo = 나중 후보` 구조는 현재 코드의 레거시 설명으로만 남는다. 목표 구조에서는 두 개를 모두 `ExecutionItem`으로 통합한다.

## 2. 최종 경계

| 구분 | 오늘 | 실행 |
| --- | --- | --- |
| 시간 범위 | 오늘 한 날짜 | 여러 날짜·주간 |
| 핵심 질문 | 지금 무엇을 하고 남은 오늘을 어떻게 바꾸지? | 조각을 어느 날·시간에 배치하고 운영하지? |
| 핵심 원본 | 오늘 ExecutionItem + DailyState | 기간 내 ExecutionItem |
| 대표 보기 | 실행 목록, 현재 상태, 다음 행동 | 주간 목록, 시간표 |
| 대표 액션 | 완료·부분·미수행, 남은 오늘 재조정 | 이동·축소·보류·재개·배치 |

두 화면은 같은 ExecutionItem을 사용한다. 복사하거나 각 화면에 별도 상태를 만들지 않는다.

## 3. 오늘 화면

오늘 화면은 앱의 당일 작업면이다.

핵심 구성:

1. 오늘 상태: 컨디션, 운영 강도, 집중 메모
2. 지금 할 조각: 우선순위와 현재 시각을 반영한 다음 행동
3. 오늘 실행 목록: 시간 있는 항목과 시간 없는 항목
4. 현실 조정: 이동·축소·보류·남은 오늘 다시 짜기
5. 실제 결과: 완료·부분 수행·미수행 입력

오늘 화면에 장기 계획 전체, 월간 통계, 과목 자료를 동시에 펼치지 않는다. 필요한 배경은 조각의 “왜 이 조각인가” 또는 AI 패널에서 확인한다.

## 4. 실행 화면

실행 화면은 여러 날짜를 운영하는 공간이다.

핵심 구성:

- 날짜별 실행 목록
- 주간 시간표
- UNSCHEDULED 후보 배치
- DATE_ONLY와 TIME_FIXED 전환
- 이동·축소·보류·재개·취소
- PlanItem과 루틴 출처 확인
- AI 제안의 주간 배치 미리보기

실행 화면은 계획을 처음 만드는 곳이 아니다. 필요하면 계획 탭 또는 AI 패널에서 PlanItem을 만들고, 실행에서는 생성된 조각을 실제 시간에 배치한다.

## 5. 오늘 진입 시 조회

```text
daily_states
  WHERE user_id = 현재 사용자
    AND state_date = 오늘

execution_items
  WHERE user_id = 현재 사용자
    AND is_deleted = 0
    AND scheduled_date = 오늘

관련 plan_items / context_items
  현재 화면에 필요한 범위만 추가 조회
```

ExecutionItem이 DailyState를 FK 부모로 가지지 않는다. 날짜 이동 때 DailyState 연결까지 바꾸는 문제를 만들지 않는다.

## 6. 실행 결과 입력

### 완료

```text
COMPLETED ExecutionRecord 생성
→ ExecutionItem 상태 DONE
→ 같은 트랜잭션으로 커밋
```

### 부분 수행

```text
PARTIAL ExecutionRecord 생성
→ 실제로 한 분량 기록
→ 남은 분량 ExecutionItem 생성
→ 두 항목을 SPLIT Event로 연결
→ 같은 트랜잭션으로 커밋
```

### 미수행

```text
NOT_DONE ExecutionRecord 생성
→ 사용자가 이동·축소·보류·취소 중 다음 결정을 선택
```

미수행 기록만으로 자동 이동하지 않는다. 다음 조정은 사용자가 직접 고르거나 AI 제안으로 검토한다.

## 7. 남은 오늘 다시 짜기

1. 사용자가 현재 상황을 말한다.
2. AI가 남은 오늘 항목의 유지·이동·축소·보류 후보를 만든다.
3. Today 목록에 ghost/diff로 표시한다.
4. 사용자가 직접 수정하거나 다시 대화한다.
5. 필요한 변경만 적용한다.
6. 서버가 version을 확인하고 Item/Event를 갱신한다.
7. Today 목록과 주간 시간표를 같은 원본으로 다시 그린다.

AI가 제안한 순간에 공식 ExecutionItem을 덮어쓰지 않는다.

## 8. 이동·축소·보류

### 이동

- 날짜 또는 시간을 바꾼다.
- 전후 배치와 version을 MOVED Event에 남긴다.
- 오늘 밖으로 이동하면 오늘 목록에서는 사라지고 실행 화면의 대상 날짜에 나타난다.

### 축소

- 제목, 예상 분량, 예상 시간 중 필요한 값을 줄인다.
- 원래 값과 변경 값을 REDUCED Event에 남긴다.
- 실제로 수행한 결과가 있다면 축소가 아니라 부분 수행 흐름을 사용한다.

### 보류

- 상태를 HOLD로 바꾸고 HOLD Event를 남긴다.
- 오늘 목록의 기본 실행 대상에서는 제외한다.
- 다시 시작하려면 RESUMED Event와 함께 PLANNED로 되돌린다.

## 9. 어제·내일과 pending

과거 날짜의 PLANNED 항목은 실패 배지가 아니라 정리 대상이다.

사용자는 다음 중 하나를 선택한다.

- 실제로 했다면 결과 기록
- 오늘 또는 다른 날짜로 이동
- 더 작게 축소
- 보류
- 취소

HOLD, DONE, CANCELLED, 삭제 항목은 정리 대상 목록에 반복 노출하지 않는다.

## 10. AI 제안 표시

리스트에서 최소한 다음 상태를 구분한다.

```text
NEW       새로 생길 조각
CHANGED   제목·날짜·시간·분량이 바뀔 조각
REMOVED   보류·취소·삭제 또는 오늘 밖으로 이동할 조각
OFFICIAL  현재 공식 조각
```

시간표에서도 같은 제안 ID와 상태를 사용한다. 리스트와 시간표가 서로 다른 변경안을 계산하지 않는다.

## 11. 사용자 언어

| 내부 모델 | 화면 표현 예시 |
| --- | --- |
| ExecutionItem | 실행 조각, 오늘 할 일 |
| ExecutionRecord | 실제 기록, 수행 결과 |
| ExecutionItemEvent | 조정 이력 |
| PlanItem | 계획 항목 |
| AIProposal | 변경안, 계획 초안 |
| ContextItem | 기억된 조건, 계획에 반영된 정보 |

내부 데이터 이름을 그대로 노출할 필요는 없지만, 같은 액션은 화면마다 같은 이름을 사용한다.

## 12. 완료 판정

- 오늘과 실행에서 같은 항목의 상태가 일치한다.
- Today에서 적용한 이동이 주간 시간표에 즉시 반영된다.
- 부분 수행 후 실제 기록과 남은 조각이 모두 보인다.
- AI 제안을 무시해도 공식 데이터는 바뀌지 않는다.
- 새로고침 후에도 적용 전 제안이 유지된다.
- 오래된 제안은 version 충돌로 최신 수정을 덮어쓰지 못한다.
- 삭제·완료·보류·취소 항목이 pending에 잘못 노출되지 않는다.
