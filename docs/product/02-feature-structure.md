# 02. 기능 구조

> 현재 기준: 2026-10-25(전면 개정. 2026-09-16판은 git 이력에 있다). 화면은 diary-ui `src/shell/MainShell.jsx`, 뷰는 `src/views/*`.
> 이 문서는 탭별 책임과 화면↔데이터 관계만 다룬다. 각 기능의 계약은 링크한 문서가 기준이다.

## 1. 전체 구조

```text
오늘      당일 실행과 재조정, 과제 마감, 수업 확인
자료      자료 업로드와 자동 분석 현황
프로젝트  프로젝트별 작업 공간 — 학습 지도·교재·기억·자료 정리·과제
계획      기간 계획 초안·확정·회고
일정      여러 날짜·시간의 배치, 시간표(루틴)·일회성 약속
기록      실제 결과와 조정 이력

AI 상담 패널  어느 탭에서나 열리는 상담(사진·일정 이미지 포함)
```

관리 단위는 프로젝트(`courses`)다. 과목·개인 개발·자격 준비가 모두 프로젝트다(10번 §5.1). 2026-08판에 있던 Quick 진입점은 만들지 않았다.

## 2. 탭별 책임

### 2.1 오늘 (`views/TodayView.jsx`, `views/today/`)

- 오늘 날짜의 실행 조각과 다음 행동
- 완료·부분 수행 기록(막힌 이유 `blockerKind` 선택 가능), 재열기
- 이동·미배정·축소·보류·재개·삭제(되돌리기 토스트)
- 과제 마감 한 줄, 지난 수업 확인 카드(`views/classcheck/`, 20번 §8)

오늘은 장기 계획을 새로 설계하는 곳이 아니다. 세부 실행 루프는 08번.

### 2.2 자료 (`views/materials/`)

- 업로드 전 목록·크기·예상 분석 시간 → 묶음 진행 카드(15번 §12)
- ZIP에서 골라 가져오기, 형식(PDF·PPTX·HWP·HWPX·IPYNB·소스 코드 등, 15번 §4-3)
- 자동 분석 상태·한도(`AnalysisOverviewBar`)

### 2.3 프로젝트 (`views/projects/`, `views/learning/`, `views/memory/`)

- 프로젝트 학습 지도(토픽·진도·자료 구간 연결, 16번), 학습 구조 편집
- 교재 패널: 교재 목차 웹 검색·정정·하위항목(17번)
- 이 프로젝트에서 기억하는 것: 진도·시험 범위·막힌 곳·해결(18번), 이번 주 수업 확인(20번)
- 자료 정리(정리안 검토·적용, 15번 §11~13), 자료 주차 확인
- 과제(마감)

### 2.4 계획 (`views/plan/`)

- 기간·강도·지시로 초안 만들기, 상담 대화에서 초안 만들기
- 초안 미리보기: 전략·항목·주간 배치, "말한 범위" 패널(`PlanScopeReport`, 21번), 근거 보기(`PlanProvenance`, 13번 §10), 항목 「자세히」
- 같은 조건으로 다시 만들기(이번 요청 제외·지정 자료), 확정, 회고(11번)

### 2.5 일정 (`views/schedule/`)

- 기간 내 실행 조각 배치(주간), Timefold 배치 미리보기
- 시간표(루틴)·예외(휴강·이동), 일회성 약속

오늘과 일정은 같은 `ExecutionItem`을 본다. 오늘은 날짜가 오늘인 항목만, 일정은 기간 전체를 보여준다.

### 2.6 기록 (`views/RecordView.jsx`)

- 완료·부분 수행 결과, 실제 시간과 메모, 이동·축소·보류·분할 이력

현재 상태와 과거 사건을 섞지 않는다. 상태는 ExecutionItem, 실제 결과는 ExecutionRecord, 조정 사건은 ExecutionItemEvent가 소유한다.
일기 API(`/api/diaries`)는 서버에 남아 있지만 지금 메인 화면에는 일기 탭이 없다.

## 3. AI 상담 패널 (`src/ai/AiPanel.jsx`)

자연어와 제품 데이터를 잇는 번역 계층이다. 패널이 보는 것과 내는 것:

| 입력 | 출력(모두 제안 — 서버가 검증해 저장하거나, 사용자가 적용해야 공식 데이터가 된다) |
| --- | --- |
| 현재 요청, 선택한 프로젝트·항목 | 상담 답변, 되묻기 카드 |
| 확인된 사실(`user_contexts`), 상담 합의(`ai_plan_briefs`) | 합의 변경(planBrief ops — 근거·승인 규칙은 21번 §3) |
| 최근 2주 실행 기록, 등록된 일정 | 일정 후보(루틴·약속 — 카드에서 승인), 계획 초안 제안 |
| 자료 근거 조회 결과, 첨부한 교재 사진(19번) | 기억할 사실(서버가 원문과 대조해 저장, 18번) |
| 일정 이미지(14번) | 추출한 일정의 검토 모달 |

(2026-10-26) 상담 AUTO 턴은 도구 단계(일정·할 일·과제 조회, 변경 제안, 말한 시간 정리, 가정 가용시간) 뒤에 답한다. 기존 루틴 회차·약속·할 일·과제를
바꾸는 제안은 변경 묶음(`ai_change_bundles`) 카드로 보이고, 사용자가 적용할 때 한 트랜잭션으로 반영된다. 작업 기록
`docs/handoff/consult-tools-2026-10-26.md`, 계획 `docs/handoff/consult-tools-plan-2026-10-25.md`.

## 4. 사용자의 하루 시나리오

1. 오늘 화면에서 오늘 조각과 지난 수업 확인을 본다.
2. 계획이 현실과 다르면 조각을 옮기거나 줄이고, 필요하면 상담에서 상황을 말한다.
3. 실행 중 완료·부분 수행을 기록한다. 부분 수행이면 한 만큼 기록하고 남은 분량은 새 조각이 된다.
4. 기록 화면에서 실제 결과와 조정 사건을 본다.
5. 다음 상담·계획이 확인된 사실과 실제 패턴을 다시 쓴다.

## 5. 화면과 데이터 관계

| 화면 | 읽는 원본 | 주로 쓰는 원본 |
| --- | --- | --- |
| 오늘 | 오늘 `execution_items`, `course_assignments`, `class_sessions` | `execution_records`, `execution_item_events`, `class_sessions`, `learning_events` |
| 자료 | `materials`, 분석 작업·묶음 | `materials`, `material_links` |
| 프로젝트 | `courses`, `course_topics`, `material_sections`, `user_contexts` | 토픽·교재·정리안 적용, `user_contexts` 수정 |
| 계획 | `ai_proposals`(초안), `plan_versions`, 생성 기록·근거 스냅샷 | `plan_versions`, `execution_items`(확정 시) |
| 일정 | 기간 내 `execution_items`, `routines`, `one_off_commitments` | 같은 표들 |
| 기록 | `execution_records`, `execution_item_events` | 기록 수정 |
| AI 패널 | 선택 + `user_contexts` + `ai_plan_briefs` + 실행 집계 + 자료 근거 | `ai_messages`, 합의, 기억, 제안 |

테이블 상세는 05번.

## 6. "왜 이 조각인가" 경로

계획 항목마다 근거(자료 구간·합의·실행 기록·마감)를 회차 안의 인용 번호로 추적하고, 확정 뒤에도 근거 스냅샷으로 다시 연다
(13번 §10, `plan_generation_traces`·provenance). 2026-08판의 `plan_item_context_links`는 쓰지 않고 지웠다.

## 7. 충돌 해결 기준

- 오늘과 일정이 같은 항목을 따로 저장하지 않는다.
- 계획은 예정, 기록은 실제를 소유한다.
- AI 제안은 미리보기이며 자동 적용이 아니다. 기억은 자동 저장이지만 출처와 함께 보이고 고치고 지울 수 있다.
- 프로젝트는 계획 재료를 제공하지만 실행 결과를 따로 소유하지 않는다.
- 루틴은 반복 원본이며, 특정 날짜에 생성된 결과는 ExecutionItem이다.
- 완료는 활동 기록이지 이해 확정이 아니다(20번 §3). 진도는 원천 + 이벤트에서 계산하는 방향이다.
