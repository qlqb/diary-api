# 18. 학습 기억 · 목차 기반 학습 목표 (2026-10-05)

목표 흐름:

```text
상담에서 진도·시험 범위·막힌 곳·해결을 말한다 → 서버가 종류·단원·출처·시각과 함께 기억(사용자가 카드를 쓰지 않는다)
→ 프로젝트 사실 카드에서 확인·수정 → 새 대화의 상담과 계획 생성(자료 선택 포함)이 같은 "확인된 상태"를 받는다
→ 교재·진도를 다시 묻지 않고, 막혔던·도움받아 해결한 단원을 먼저 본다
```

성공 기준(묶음 전체): 사진을 올리고 같이 공부한 뒤, 새 대화에서 계획을 요청해도 교재·진도를 다시 묻지 않고 확인된 어려움과 해당
본문을 활용한다. 이번 단계(1 + A)는 사진 없이 성립하는 부분이다. 상담 사진 첨부(B)·사진 본문의 계획 활용(C)은 다음 단계.
구현 계획·리뷰 기록: `docs/handoff/study-memory-plan-2026-10-05.md`(v3), 작업 기록 `docs/handoff/study-memory-2026-10-05.md`.
DB는 05번 §24, API는 `api-spec.md`(Study Memory), 마이그레이션 `docs/sql/2026-10-05-study-memory.sql`.

## 1. 기억은 새로 만들지 않고 넓혔다

`user_contexts`(상담 자동 저장, 2026-09-19)에 종류(`fact_kind`)·시험 이름·도움 수준·근거 발화 시각(`said_at`)·본문 키를 더했다.

| 종류 | 뜻 | 현재 값 |
|---|---|---|
| PROGRESS | **수업에서** 어디까지 나갔나(사실) | 과목당 하나 |
| EXAM_SCOPE | 시험 범위(시험 이름별) | 과목·시험 이름당 하나 |
| DIFFICULTY | **내가** 막힌 곳 | 해결이 가리킬 때만 닫힘 |
| RESOLVED | 막혔던 것을 풀었다(혼자/도움받아) | 최근 30일만 상태에 실림 |
| GOAL·PREFERENCE·CONSTRAINT·OTHER | 그 밖 | — |

수업 진도와 내 이해는 다른 사실이다 — 묶음·문구·프롬프트 모두 섞지 않는다.

## 2. 저장 규칙(서버가 지킨다)

- **사용자 말로 인정**(STATED·SELF_REPORT): 인용이 이번 발화 안에 있고, 문장 속 숫자가 전부 발화에 있어야 한다(연도·앞자리 0은 봐준다).
  아니면 AI 추정. 모델은 OBSERVED를 만들 수 없다.
- **단원 연결**: 그 과목의 살아 있는 단원만. 사용자 말로 인정하려면 사용자가 그 단원을 실제로 가리켰어야 한다(번호가 단원 표기와 함께 —
  "Unit 1"은 Unit 10이 아니다). 제목이 같은 단원은 목차 원본 순번(`course_topics.source_toc_seq`)으로 가른다.
- **현재 상태 대체**(진도·시험 범위): 과목 행을 잠그고(READ COMMITTED — 잠금을 기다린 뒤 다른 턴의 저장을 본다) 같은 종류의 살아 있는
  값과 비교. 대체는 STATED이면서 **인용 자체가** 그 주장을 담을 때만(숫자가 인용 안에, 부정·미완·질문·가정 표지 없음). 순서는
  (발화 시각, 메시지 번호)이고 같은 초면 메시지 번호가 큰 쪽, 사용자 수정과 같은 초면 수정이 이긴다 — 늦게 끝난 옛 턴은 정정을 되돌리지
  못한다. 추정은 확인된 값을 덮지 않는다. 한 턴에 여럿이면 마지막 하나.
- **막힘 → 해결**: 해결이 그 막힘 번호를 가리키고(resolves) 사용자 말(STATED·SELF_REPORT)일 때만 닫는다. 단원은 대상에서 승계하고,
  다른 단원을 말했으면 닫지 않는다(같은 단원의 다른 막힘도 그대로).
- **중복·승격·철회**: 같은 내용이 있으면 새로 만들지 않고, 추정이던 것을 사용자가 말하면 근거만 올린다. 지운 것과 같은 내용은 이력
  전체에서 막는다(본문 SHA-256 키, 예전 행은 전부 정규화 비교).
- **종류의 단서**: 진도·시험 범위·막힘·해결로 받으려면 인용에 그 종류의 단서 말이 있어야 한다(진도: "까지·나갔·배웠·진도"…, 해결:
  "풀었·해결·이제 …수 있"…). 없으면 AI 추정. 막힘을 닫는 해결도 해결 단서가 있어야 한다.
- **자료 원문을 실은 턴**: 원문을 본 모델의 기억은 버린다(주입 방어 유지). 대신 사용자 발화만 보고 다시 뽑는 보조 호출
  (`UserMemoryExtractor`, 기능 `MEMORY_EXTRACT`)이 같은 검증을 탄다 — 입력은 발화 + 번호 참고용 데이터(단원 목록·열린 막힘)뿐, 원문·AI 답변
  없음. 이 입력에도 외부 데이터(단원 제목)가 섞이므로 **모델이 쓴 문장은 버리고 사용자가 쓴 말(인용) 그대로를 저장**하며, 인용이 발화에
  없거나 종류의 단서가 없으면 버린다. 기억할 신호가 없는 발화엔 부르지 않고, 상담 한도와 따로 하루 40회 상한(동시 요청으로 몇 회 넘을 수
  있다 — 예약식 상한은 다음에), 실패해도 턴은 성공.
- **모델이 빠뜨린 기억**: 발화에 진도·막힘·해결 신호가 분명한데 모델이 과목 사실 기억을 하나도 내지 않으면 같은 보조 추출을 부른다
  (실호출에서 "Unit 4까지 나갔어"·"이제 만들 수 있어"를 빠뜨린 것을 재현). 다른 기억은 그대로 두고 빠진 것만 보탠다.
- **다시 말함**: 같은 내용을 다시 말해도 새로 만들지 않는다. 대신 같은 대체 규칙을 탄다 — 확인된 값은 발화 시각을 새로 하고(그 사이 늦게
  끝난 옛 턴이 덮지 못하게), 추정이던 것은 근거를 올리되 진도·시험 범위면 인용이 그 주장을 담을 때만 올리고 다른 현재 값을 대체한다.
- **기간**: 기간이 정해진 기억("이번 주만")은 기간이 지나면 상태에 싣지 않고, 실을 때 "M/d까지만"을 붙인다.
- **철회**: 자동 저장과 같은 과목 잠금 아래 처리한다.
- **사용자 수정**: 내용과 함께 종류·단원·도움 수준·시험 이름을 고칠 수 있다(생략 칸은 보존, 단원은 그 과목 것만). 고친 진도는 지금의
  사용자 말이라 다른 진도를 대체한다. 추정을 "맞아요"로 확인한 진도도 현재 값이 된다.

## 3. 확인된 상태 블록 (`ProjectStateService`)

교재(교재 칸 그대로, 출처 포함) → 수업 진도 → 실제 수업 정정(최대 5) → 시험 범위·범위 제외 → 막힌 곳(m번호·단원) → 해결 →
목표류 → AI 추정. 과목당 14줄, 줄당 120자. 넘치면 추정 → 해결 → 목표류 순으로 줄 단위로 뺀다. 출처 라벨은 서버가 붙인다.

| 받는 곳 | 방식 |
|---|---|
| 상담(과목 대화) | 화면 상태 블록의 3,500자 잘림 밖에 고정으로. 실린 기억 id만 장기 컨텍스트에서 뺀다 |
| 상담(계획을 다루는 전역 대화) | 기억이 있는 최근 과목 3개, 과목당 6줄 |
| 자료 선택 | 같은 상태 줄(라벨 포함). 상태 지문이 선택 재사용 지문에 들어간다 — 진도·막힘을 고치면 다시 고른다 |
| 계획 생성 | 과목 아래 같은 블록(줄마다 근거 번호). 규칙: 교재·진도·시험 범위는 questions·missingInformation에 넣지 않는다, 막힌·도움받아 해결한 단원을 먼저 본다(범위 제외가 앞선다) |
| 학습 항목 목록 | 막힌 곳·해결한 단원은 "막힌 곳(10/5) — 먼저 볼 후보"·"도움받아 해결(10/5) — 혼자 다시 해 보기 좋은 후보"를 붙여 **선택과 무관하게 필수로** 싣는다(목록에 없으면 계획이 그 단원을 가리킬 수 없다 — 실호출에서 Unit 1만 나온 원인). 확인된 수업 진도가 있으면 기록 기준 "← 첫 미학습"(목차 트리면 Unit 1)을 붙이지 않는다 |
| 초안 최신성 | 생성 때 과목별 상태 지문을 요청 맥락에 저장. 지금과 다르면 "오래됨"(추정 확인처럼 같은 행이 바뀌어도). 인용한 기억은 상태 변경뿐 아니라 수정 시각이 생성 때보다 늦어도 "오래됨" |

## 4. 1번 — 목차 기반 학습 목표·AI 연습

- 계획 항목에 학습 목표(`goal`, 60자). **근거는 서버가 인용으로 정한다**: 수락된 사용자 목표를 그대로 옮겼을 때만 USER("내가 정한 목표"),
  같은 과목 자료 구간을 인용하면 MATERIAL_AI("자료 기반 AI 목표"), 같은 과목·단원의 목차 항목만 인용하면 TOC_AI("목차에서 추론").
  근거가 없거나 과목·단원이 다르면 버린다. 모델이 바꾼 목표는 사용자 목표가 아니다.
- 목차 제목이 표현·문법을 드러내면(예: "I'm doing my homework right now") 그 단원의 목표를 추론하고 말하기·쓰기 연습을 만들 수 있다.
  목차만 인용한 연습은 AI_PRACTICE("AI가 만든 연습 — 교재 문제가 아니에요")로 표시한다. 대화문·문제 번호·정답·쪽 안 내용은 여전히 만들지 않는다.
- 목적 규칙(시험·복습·독학)이 목차만 있는 과목을 "목차 훑기"로 보내던 문구를 "진도·막힌 단원 근처의 추론 목표와 AI 연습"으로 바꿨다.
- 상담·선택·계획의 목차 항목 줄: `(교재 p.12 — 교재 목차 3번째, 제목만 확인)`. 정리 프롬프트: 같은 교재 목차 안에서 번호가 다르면 다른 항목.

## 5. 화면

- 프로젝트 작업 공간 > 교재 구역 아래 **이 프로젝트에서 기억하는 것**: 교재 한 줄, 묶음(수업 진도·시험 범위·막힌 곳·해결한 것·그 밖),
  줄마다 단원 칩(목차 순번)·출처 칩·날짜, [고치기](내용·종류·단원·도움)·[지우기](그 자리 확인)·추정만 [맞아요]. 입력 폼 없음.
  상담이 기억을 남기거나 고치면 다시 읽는다.
- 계획 항목: "목표: …" + 근거 칩(툴팁). AI 연습 라벨 옆 "교재 문제가 아니에요".
- 상담 "내가 이해한 내용": 종류·단원을 함께 보인다.

## 6. 하지 않은 것

- 새 기억 테이블·벡터 검색·과거 대화 원문 검색. 판 이름(개정N판) 분리(완료 조회 재수집 절차와 함께 다음에).
- 상담 사진 첨부(B)·사진 본문의 계획 활용(C) — 계획 v3 §6.
- CI에서 DB 통합 테스트 실행(저장소에 전체 스키마가 없다 — 기존 `excludeDbTests` 관행).
