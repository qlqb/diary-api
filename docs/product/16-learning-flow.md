# 16. 계획 이해 · 학습 실행 · 교재와 실제 수업 반영 (2026-09-29)

목표 흐름:

```text
자료와 사용자 맥락으로 계획 생성 → 목표·범위·가정 이해 → 직접 수정·적용 → 첫 학습 시작
→ 수행 결과 기록 → 다음 상담·계획의 조정안에 반영
(필요할 때) 교재 연결·실제 수업 진행 정정 → 토픽 구조 변경 전후 검토
```

학습 지도 정리는 공부·계획 생성의 필수 선행 작업이 아니다. DB는 05번 §22, API는 `api-spec.md`(Learning Flow),
마이그레이션 `docs/sql/2026-09-29-learning-flow.sql`.

## 1. 모르는 과목의 계획도 판단할 수 있다

### 1.1 판단 영역(「이번 계획은 이렇게 봤어요」)

기본 화면은 핵심만: 목표 · 도달점 · 프로젝트 순서와 할 일 순서(앞 3개) · 왜 이렇게 · 이 계획이 참고한 내 상태 ·
**자료 근거** · **분량·난이도** · 확인하지 못한 가정 · 빼거나 읽지 못한 범위 · 내가 범위에서 뺀 항목. 유지한 결정·프로젝트별
이유·달라진 점·사용자 상태 목록은 [자세히 보기]. 확정한 계획 화면에도 같은 영역(접힘)이 있다.

- 전부 이미 받은 값에서 계산한다(`lib/planUnderstanding.js`) — 초안 판단(strategy), 그 회차에 실제로 준 정보(provenance의
  USER_CONTEXT·EXECUTION_HISTORY·PLAN_BRIEF), 서버가 센 자료 읽기 결과(materialSelection). 모델을 다시 부르지 않는다.
- **자료 근거와 적합성을 섞지 않는다.** "원문 N곳을 읽음 · M곳은 일부만 · K곳은 못 읽음"은 근거이고, "분량·난이도"는
  수행 기록이 있으면 "실제 수행 기록을 참고한 추정", 자기평가만 있으면 "내가 말한 상태를 참고한 추정", 없으면 "AI 추정"이다.
  원문을 읽었다는 이유로 사용자가 해낼 수 있다고 쓰지 않는다.

### 1.2 항목: 할 일 · 완료 기준 · 시작 자료

- 생성기는 설명을 "행동 · 완료: 기준"으로 합쳐 저장한다(실행 조각에 설명 칸 하나만 남기 때문). 화면은 이 꼬리만 떼어
  **할 일**과 **완료 기준**을 함께 보인다. 예전에는 완료 기준이 있으면 설명(유일한 행동 문장)을 숨겨 행동이 사라졌다.
- **시작 자료(startSource)**: 그 항목이 인용한 첫 자료 구간을 회차 스냅샷에서 되짚어 지금 자료와 대조한 값
  (`StartSourceResolver`). 파일·위치·PDF 쪽, 상태 AVAILABLE / CHANGED(파일이 바뀜 — 옛 쪽으로 열지 않는다) / DELETED.
  PDF가 아니면 쪽 이동 대신 위치를 글로 적는다. 모델이 새로 쓴 값이 아니다.
- 새로고침한 초안의 goalSummary는 전략의 goal로 되살리고, 확정 요청에 목표가 없으면 전략 목표를 계획 목표로 쓴다.

## 2. 적용한 뒤 실제로 시작한다 — 학습 실행 작업 공간

- 오늘·계획·일정·프로젝트의 항목 제목을 누르면 같은 작업 공간이 열린다(`ItemWorkspace`, 셸이 연다). 같은 실행 항목
  한 행을 보므로 화면별 원본·진도가 없다. 여기서 한 기록은 다른 화면에 그대로 보인다.
- 먼저 보이는 것: **첫 행동 · 시작 자료 · 완료 기준**. 펼쳐 보는 것: 단계별 안내와 내 메모 · 시작 도움 · 원문 근거 · 지난 기록.
- `GET /api/execution-items/{id}/workspace`는 모델을 부르지 않는다. 단계 안내는 펼칠 때(없으면 그때 한 번 만든다).
- **정체성**: 안내·메모·시작 도움은 그 항목을 만든 제안 항목(proposal_item)에 붙는다 — 초안에서 본 안내가 적용 뒤에도,
  부분 수행으로 남은 조각에도(source_execution_item_id를 거슬러) 이어진다. 적용 뒤 줄이기·남은 분량으로 제목·설명이 바뀌면
  "처음 항목 기준 안내"라고 알린다(changedSinceDraft). 원문·항목이 바뀌면 안내는 STALE로 보이고 [지금 원문으로 다시 만들기].
- **메모**는 안내 단계가 없어도 남긴다(단계 없는 행, 나중에 만든 단계가 같은 행을 채운다).
- 직접 만든 항목(제안 원본 없음)은 안내를 지어내지 않고 그렇다고 말한다(NO_ORIGIN).

### 2.1 시작 도움

"어디서 시작할지 모르겠어요" / "너무 커요"(+ 자유 글). 모델 1회. 그 항목이 인용한 구간만 준다.

- 항목의 범위·시간·마감·배치를 바꾸지 않는다. 전체 계획을 다시 만들지 않고 진단을 요구하지 않는다.
- 출력: 첫 행동(1~2문장) · 필요할 때만 짧은 시작 활동(5~15분, 단계 4개까지) · 자료 위치(구간이 있을 때만).
- 요청이 분량·범위 변경이면 scopeChangeRequested로 표시하고 "계획 조정 상담"으로 안내한다(도움으로 처리하지 않는다).
- 인용 구간이 없으면 grounded=false("자료 원문 없이 항목 설명만으로 만든 안내")이고 서버가 자료 위치를 버린다.

## 3. 실제 수행이 다음 계획을 조정한다

완료·일부 수행에 "어떻게 했나요(선택)": **혼자 해냈어(SOLO) / 설명·예제를 보고 했어(GUIDED)**, **막힌 단계**(글).
쓰지 않아도 완료된다. 고르지 않으면 필드를 보내지 않는다. 작업 공간의 지난 기록에서 고칠 수 있다(결과·분량은 그대로).

다섯 가지를 섞지 않는다 — 계획·상담 프롬프트 규칙과 기록 문장이 같은 말을 한다:

| 사실 | 뜻 |
|---|---|
| 기록 없음 | 알고 있는지 모른다(모른다는 증거가 아니다) |
| 수업·자료를 접함 | 혼자 할 수 있는지는 모른다 |
| 설명·예제를 보고 수행 | 그 활동에 지원이 필요했다 |
| 혼자 수행 | 그 활동을 혼자 해낸 근거가 있다 |
| 완료 | 활동의 수행 상태이지 단원 전체의 이해 확정이 아니다 |

- 기록 문장: `사용자 진술: 설명·예제를 보고 수행함(이 활동에 지원이 필요했음) · 막힌 단계: "…"`. 남기지 않았으면 아무것도 붙지 않는다.
- 계획 프롬프트: 한 번의 성공·막힘을 과목 전체로 일반화하지 않는다, 늦어짐은 지식 부족의 근거가 아니다, 기록이 없거나
  "처음 본다"만으로 1주차부터 재배치하지 않는다. 기록 때문에 바꾸면 그 범위에만, `strategy.changes`에 "#기록번호 기록: …"으로.
  확정된 항목은 existingItems 제안으로만(덮어쓰지 않는다).
- 도움받은 기록이 있으면 작업 공간이 [조정안 상담하기]를 준다(과목 전체를 다시 짜지 말라는 말을 함께 보낸다). 계획은 저절로
  바뀌지 않는다 — 상담 → 초안 → 선택 적용.

## 4. 교재와 수업자료를 하나의 학습 구조에

### 4.1 무엇이 막혀 있었나

- 교재 정보(제목·저자·출판사·ISBN)를 저장하는 길은 옛 수동 [구조 분석] 하나였다. 자동 분석(CONTENT)은 교재 필드를 만들지
  않았고, 자동 분석 작업이 생기면(업로드마다) 그 버튼이 숨겨졌다 — 사실상 닿을 수 없었다.
- 옛 분석의 적용은 토픽을 **덧붙이고**(중복 방지 없음) 교재 칸은 빈 칸만 채웠다. 새 정리(tidy)와 공존하면 같은 교재·항목이
  서로 다르게 적용될 수 있었다.
- 실제 목차·본문을 올려도 토픽이 안 생기는 경우는 원인이 다르다: 정리는 사용자가 누를 때만 돌고, 목차의 계층은 구간 추출에서
  사라지며(구간은 평평하다), 큰 목차는 출력 한도에 걸릴 수 있었다.

### 4.2 바뀐 것

- **규칙 추출**(`TextbookExtractor`, 모델 없음): 원문 단위(PDF 쪽 등)에서
  - 어느 책인가 — 체크섬이 맞는 ISBN, 이름표가 붙은 값(지은이·펴낸곳·도서명), 판권면 줄의 판(개정 N판·N판·초판·Nth edition).
    이름표 없는 큰 글씨 제목은 추측하지 않는다. 근거는 원문 줄 그대로와 그 단위 번호.
  - 그 책의 범위 — "목차·차례·Contents" 머리가 있는 쪽과 목차 모양 줄이 이어지는 쪽에서 번호·제목·쪽수. 3개 미만이면 없음.
- (자료, 해시, 규칙 판)마다 한 행(`material_textbook_extracts`) — 재분석·재시도·동시 조회가 행을 늘리지 않는다.
  프로젝트를 열면(교재 구역 GET) 아직 없는 자료를 읽는다. 분석 전 자료는 추출 텍스트로 읽고, 둘 다 없으면 "읽는 중"으로 센다.
- **검토·적용**: 교재 구역이 후보를 근거와 함께 보인다. 비어 있는 칸만 기본으로 고르고, 지금 값과 다른 칸은 두 값을 나란히
  보이며 사용자가 골라야 바뀐다. 적용 요청은 화면이 본 지금 값(expected)을 함께 보내고 다르면 409. 교재 출처(USER/MATERIAL)를
  남긴다. 외부 도서 검색은 쓰지 않았다(판 일치 여부는 원문에 적힌 것만).
- **목차 → 첫 골격**: 트리가 비어 있으면 정리 작업이 목차를 골격 ADD로 바꾼다(`TocSkeleton`, 장 = 변경 하나, 절은 자식, 깊이 3,
  출처 자료·"교재 p.N"). 모델은 골격을 입력으로 받아 강의·실습 구간을 골격 tempId에 LINK하고, 교재에 없는 수업 내용만 ADD한다.
  모델이 같은 장을 또 만들면 뺀다. 트리가 있으면 목차를 입력으로 주고 빠진 장·절만 제안하게 한다.
  목차는 범위이지 진도가 아니다 — 수업에서 다룬 근거가 없다고 빼거나 완료로 보지 않는다.
- **책 이름만**: TITLE_ONLY — "목차를 아직 확보하지 못했어요 … 지금 자료로도 계획과 학습은 그대로"와 올릴 것을 말한다.
- **옛 [구조 분석] 버튼**: 새 초안을 만드는 길을 닫았다. 이미 검토 중이던 옛 초안은 그대로 검토·적용·버릴 수 있다.

## 5. 실제 수업에 맞춰 정정하고 구조를 개편한다

### 5.1 네 가지를 다른 데이터로

| 요청 예 | 작업 | 저장 | 트리 |
|---|---|---|---|
| 교재 5장을 3장보다 먼저 수업했어 | CLASS(주차·"~ 다음에") | `topic_class_progress` | 그대로 |
| 이 실습은 3주차야 | MATERIAL_WEEK / CLASS(week) | `material_week_assignments`(USER) / `topic_class_progress` | 그대로 |
| 이번 시험에는 이 단원이 빠져 | SCOPE_EXCLUDE(label) | `course_scope_exclusions` | 그대로 |
| 이 항목은 너무 넓으니 나눠줘 | SPLIT(근거 구간) | 트리 | 바뀜 |
| 이 둘은 같은 내용이야 | MERGE(근거 비교) | 트리 | 바뀜 |
| (교재 구조 자체를 바꿔) | MOVE(afterTopicId) | 트리 | 바뀜 |

- 순서만 달랐다면 토픽을 복제하거나 구조를 재생성하지 않는다(CLASS만).
- 자료 번호를 실제 주차로 단정하지 않는다 — MATERIAL_WEEK는 사용자가 말한 주차만.
- 예정(강의계획서)과 실제가 다르면 실제는 이 표들이고, 계획 프롬프트에 "[실제 수업 진행 — 사용자가 정정한 것]"으로 싣는다.

### 5.2 학습 구조 조정 = 정리안

직접 조작과 말로 한 요청 모두 **정리안**(검토 → 선택 적용)으로 들어간다. 따로 적용하는 길이 없다 — 전후 비교·제외·제목
수정·충돌 감지·기록 보존을 정리안 하나가 맡는다.

- 직접 조작(학습 지도에서 항목 선택 → 구조 조정): 이름 · 위/아래(끼워 넣기) · 다른 항목 아래로 · 합치기 · 나누기 ·
  실제 수업 주차/순서 · 범위에서 빼기. 모아서 [검토로 보내기].
- 말로 한 요청(정리 구역의 [학습 구조 조정]): [조정안 만들기] — 모델 1회가 네 가지를 구분해 작업을 고른다. 분할·병합은 그
  항목들에 실제로 연결된 구간만 인용할 수 있고, 근거가 없거나 모호하면 작업 대신 되묻는다. [자료를 다시 보며 정리] — 정리
  작업에 지시를 붙여 비동기로.
- 열린 정리안이 있으면 거기에 더하고(판을 올린다 — 옛 화면의 적용은 막힌다), 없으면 새 정리안. 열린 안이 지금 트리보다
  오래됐으면 더하지 않는다(409 E409_039). 사용자가 낸 변경(by=USER/REQUEST)은 AI가 정리안을 다시 만들어도 새 판으로 옮긴다.
- 정리안 화면: [구조 전후 보기](고른 변경만, 실제 수업·범위는 표시로), 변경마다 누가 냈는지, 걸린 기록(남은 할 일·끝낸 것·
  자기평가·진도) — "기록은 옮기거나 지우지 않아요".
- 적용: 트리 작업이 없으면 트리 판을 올리지 않는다. 정정은 같은 트랜잭션에서 쓴다. 재분석·자동 분석·정리는 이 표들을 쓰지
  않으므로 다음 분석·재진입·다음 계획에서도 정정이 남는다.

### 5.3 기록 보존

- 이름·순서·이동: id 유지 — 기록이 따라간다.
- 병합: 흡수된 항목은 보관(merged_into), 실행 항목·자기평가·진도는 **옮기지 않는다**. 살아남은 항목에 "합친 항목의 끝낸 일
  N개 · 상태 확인 필요"로 알린다(학습 지도). 완료로 승계하지 않는다.
- 분할: 원래 항목에 기록이 남고 하위는 새로 시작.
- 범위 제외는 완료가 아니다. 진도·기록은 그대로이고 계획 후보에서만 빠진다(사유 `SCOPE:이름`). 학습 지도에서 풀 수 있다.
- 이미 확정한 계획과 완료 이력은 구조 변경으로 바뀌지 않는다.

## 6. 알려진 한계

- (2026-10-04) 교재 이름만 있을 때 웹에서 목차를 찾는 흐름은 17번 문서. 강의계획서 표의 교재 칸도 읽는다.
- 교재 규칙 추출은 한국어·영어의 흔한 판권면·목차 모양만 읽는다. 스캔 PDF(텍스트 없음)와 표 형식 목차, 쪽수가 줄 밖에 있는
  목차는 놓칠 수 있다 — 그때는 "목차 미확보"로 말한다(만들어 내지 않는다).
- 제목은 이름표가 있을 때만 후보가 된다(대개 사용자가 적는다).
- 시험 범위 제외는 이름(label)으로 구분할 뿐 시험 일정·마감과 연결하지 않는다(과제·일정 모델 밖).
- 실제 수업 순서는 사용자가 정정한 항목만 순서를 갖는다. 나머지는 모른다(교재 순서로 추정하지 않는다).
- 직접 조작의 [나누기]는 근거 구간을 고르지 않는다(자식은 새로 시작). 근거를 붙인 분할은 말로 요청하거나 정리에서 나온다.
